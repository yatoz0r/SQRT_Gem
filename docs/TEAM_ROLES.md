# Распределение ролей и матрица ответственности команды (SQRT_Gem)

> **Статус документа:** Организационная структура проекта  
> **Размер команды:** 5 специалистов (согласно Разделу 20 ТЗ)

---

## 1. Состав команды и зоны ответственности

| Специалист / Роль | Должность | Ключевые задачи | Ожидаемый вклад |
| :--- | :--- | :--- | :--- |
| **Участник 1: Руководитель проекта (PM)** | Project Manager / Scrum Master | Координация команды, контроль сроков по диаграмме Ганта, управление рисками, экономическая модель, приемочные испытания. | Организация процессов, защита проекта, соблюдение сроков. |
| **Участник 2: Разработчик ядра** | Core Math Developer | Реализация лексера, парсера (Shunting-Yard), высокоточной арифметики `decimal_math`, расчет $\sqrt{x}$ до 1000 знаков, обработка математических исключений. | Высокопроизводительное, строгое математическое ядро. |
| **Участник 3: Разработчик UI** | Frontend / Desktop Developer | Разработка графического интерфейса (PySide6), система локализации (4 языка), динамическая смена тем, эргономика рабочего места калькулятора. | Отзывчивый, удобный и интуитивно понятный GUI. |
| **Участник 4: Инженер по тестированию** | QA Automation Engineer | Разработка unit-, интеграционных, e2e, black-box и white-box тестов, проверка математической точности (эталоны), контроль покрытия ядра ≥80%. | Гарантия безошибочности и соответствия ТЗ. |
| **Участник 5: DevOps / Документатор** | Build & Release Engineer / TechWriter | Настройка CI/CD, сборка PyInstaller, инсталляторы (Inno Setup для Windows, скрипты Linux), механизм обновления, оформление документации. | Воспроизводимая поставка дистрибутивов и чистая документация. |

---

## 2. Матрица ответственности (RACI)

- **R** — Responsible (Исполнитель)
- **A** — Accountable (Ответственный / Утверждающий)
- **C** — Consulted (Консультант)
- **I** — Informed (Информируемый)

| Компонент / Задача | PM | Core Dev | UI Dev | QA | DevOps |
| :--- | :---: | :---: | :---: | :---: | :---: |
| Анализ требований и ТЗ | **A** | C | C | C | C |
| Архитектура ядра и парсер | I | **A / R** | C | C | I |
| Графический интерфейс (GUI) | I | C | **A / R** | C | I |
| Полиязычность (RU/EN/ES/ZH) | I | I | **R** | C | **A** |
| Тестовое покрытие (≥80%) | I | C | C | **A / R** | I |
| Инсталляторы и чистое удаление | I | I | I | C | **A / R** |
| Механизм обновлений (Updater) | I | C | C | C | **A / R** |
| Документация (Manual, Arch, Eco) | **A** | C | C | C | **R** |

---

## 3. Взаимозаменяемость (Backup Plan)

1. При временном отсутствии **Разработчика ядра** его задачи подхватывает **Инженер по тестированию** (глубоко знающий математические контракты и алгоритмы) либо **PM** (в части алгоритмической проверки).
2. При отсутствии **Разработчика UI** верстку виджетов и интеграцию сигналов выполняет **DevOps** или **Разработчик ядра**.
3. При отсутствии **DevOps** задачи сборки и автоматизации выполняет **Разработчик ядра**.
